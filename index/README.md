# The library index

`index/index.jsonl` in every project (shipped in `template/index/`) holds one JSON object per line: every scene,
transition, helper and lyric plan of the engine, every tool, and every `## ` section of the skill's manuals. `grep`
returns whole entries, so nothing else needs loading:

```bash
grep -i 'rain' index/index.jsonl                      # by word
grep '"kind":"transition"' index/index.jsonl          # every transition
grep '"fits":\["vocaloid"' index/index.jsonl          # what the vocaloid style offers
```

Then start with the indexed range (`where`, read with offset / limit). Read surrounding code or the full file when needed to understand dependencies, initialization, shared state, or behavior.

It is generated by `node tools/build_index.mjs` (run by `tools/verify.mjs`), from the code: registrations
(`Z.scene`, transitions, `addPlan`), helper assignments, file headers and the comments above a definition. It is never
edited by hand, so it cannot drift. The film's own `engine/scenes/<film>.js` is indexed too (`fits: film`), so other
builders and later rounds find it.

## Fields

| field | what |
|---|---|
| `id` | `<kind>:<name>`, e.g. `scene:train`, `helper:D.travel`, `manual:references/04-asset-generation#12` |
| `kind` | `scene` · `type-scene` · `transition` · `helper` · `lyric-plan` · `tool` · `check` · `manual` |
| `fits` | the preset it was made for (`vocaloid`, `interface`, `magazine`), `shared`, or `film` (the film's own): a technique any film may use; a preset's overall look stays the preset's |
| `does` | what it shows or does, from the header or the comment above it |
| `where` | `path:first-last` (project-relative; `<skill>/…` for manuals) |
| `use` | the smallest call |
| `lines` | the size of that range: what opening it costs |
| `tags` | optional, from a `// @index tags: a b | fits: x y` comment above the definition |
| `status` | `demo-specific` when the header names demo shots: learn from it, or call it with care |

To improve an entry, improve the code comment above the definition (one line on what the viewer sees), or add an
`@index` line; then run `node tools/build_index.mjs`.
